# 周发布核对口径

## 来源与范围

- 时间：上一自然周周一 00:00 至周日 23:59（Asia/Shanghai），按业务字段中的发布日期判断。
- 客户事实：抖音客户发布表、小红书客户发布表、独立端客户表【独立端-内容发布】。
- 机构事实：部门 Base 中当前全部“机构 X 焦尾 执行表”，基线 13 张。
- 匹配读取完整客户与机构记录，不在读入客户时先按周裁剪。报告对象由双方各自周内记录确定；周外客户仅可凭同作品强证据与周内机构关联，不把周外无关记录计为本周发布或异常。双方周内计数各保留原日期，不因关联把补登记日期当成实际发布日期。

## 比较字段

只比较发布事实与归属：机构、达人、平台、跨月日期、真实发布链接或作品 ID/GID，以及机构进度。规则以 `config/business-policy.json` 的 `weeklyPublicationReconciliation` 为准。同一公历年月内日期无论差几天都不提醒；年月不同单列“跨月归属待核”（跨年同月份也不同），保留两边日期且不自动改表。达人名称先做 NFKC、空格、分隔符和大小写归一化。互动数据不参与比较。

## 匹配与差异

匹配顺序：

1. 规范化真实发布链接及其作品 ID 相同；链接指向的作品优先于手填 GID，冲突必须保留为差异；
2. 无法从真实链接识别作品时，检查作品 ID/GID 或相同短链，仍须排查相互冲突的证据；
3. 同机构、同平台、规范化达人名只能作为弱候选，不能跨多期或冲突作品猜测对应，也不靠日期接近选中某一期。忽略同月日期差异不等于仅凭同名就可以合并合作。

独立端来源没有机构色块，先限定机构表`项目/专项=独立端+PC端`（兼容“双端”）和独立端内容方向，再走上述证据顺序。PC 端仍按工作任务独立核对；两端是同一达人两期内容，不能合并或互相代替。

抖音 `/user/...` 中的 `group_id`、`from_gid`、`vid` 应与 `/video/<id>` 归为同一作品；短链应展开后再比较。单元格标题、纯文本、富文本展示不同，但真实链接一致时不算差异。

差异类型包括：客户表有而机构表缺失、客户已发布而机构进度未更新、机构表已发布而客户表缺失、机构归属/昵称/平台/跨月日期/发布链接或作品 ID 不一致，以及多条候选无法消歧的待核。同作品 ID 或真实发布链接一致时，昵称少字等保留为“昵称登记差异”，不报作缺记录；不得统一删除“的”等字或使用模糊昵称自动认定同一达人。

客户表缺记录只能说明客户登记暂缺。是否机构漏填周执行文档须另取执行文档证据，不直接推定原因或自动从机构表补客户记录。

机构表中“已发布”但发布日期为空的记录，若能以作品 ID/链接与客户表上周记录命中，则正常参与核对；若没有任何周范围证据，不得擅自归入上周，也不得据此报客户表漏登。

客户日期显示未带年份时，应复核原始日期值，不把当前年份或核对周年份硬补进去。时间戳按 Asia/Shanghai 换算；年份仍无法确定的保留为日期未知，有同作品周内关联时提示日期待核，不算核对通过。

## 防误报

- 机构是硬边界，但作品 ID/真实发布链接的强证据可以暴露“机构归属不一致”。
- 同达人多期合作不合并。
- 客户表同一作品重复行先按平台+作品 ID/规范化链接去重，并把重复情况记录为待核。
- 任一来源分页未读全、字段结构在分页期间变化、关键字段缺失或机构表不足 13 张时直接失败。普通协作编辑导致 revision 变化时，本轮已读分页组成只读快照，期间新增改动留给下一次核对，不因此整轮失败。
